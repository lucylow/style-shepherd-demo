# Recommendation Audit Trail System

This implementation adds a complete audit trail system for recommendation generation, ensuring full reproducibility and transparency.

## Overview

Every recommendation generated by the LLM is now stamped with:
- The **model prompt** used
- **Source documents** (IDs, titles, URLs, excerpts, retrieval scores)
- **User & query context** (including Verisense profile snapshot)
- A cryptographic **integrity hash**
- Persisted JSON evidence files under `logs/recommendations/`

## Files Created

### Services
- `server/src/services/verisenseClient.ts` - Fetches user profiles from Verisense/SenseSpace proxy
- `server/src/services/retrieval.ts` - Mock RAG retrieval (replaceable with Searchable/Verisense doc index)
- `server/src/services/recommendationLLM.ts` - LLM wrapper for recommendation generation

### Utilities
- `server/src/utils/hash.ts` - SHA-256 integrity hash computation

### API Routes
- `POST /api/recommendation/generate` - Main endpoint for generating recommendations with audit trail

### Logs
- `logs/recommendations/` - Directory for recommendation evidence files
- `logs/recommendations/index.json` - Index of recent recommendations (last 200)
- `logs/demo-evidence.json` - Example evidence file

## Usage

### Generate a Recommendation

```bash
curl -X POST http://localhost:3001/api/recommendation/generate \
  -H "Content-Type: application/json" \
  -d '{
    "user_id": "user123",
    "query": "What should I wear to Thanksgiving?"
  }'
```

### Response Format

```json
{
  "recommendation_id": "rec-1690000000000",
  "path": "/path/to/logs/recommendations/rec-1690000000000.json",
  "recommendation": {
    "id": "rec-1690000000000",
    "user_id": "user123",
    "query": "What should I wear to Thanksgiving?",
    "created_at": "2025-11-26T12:00:00Z",
    "model": { "name": "mock-llm", "params": { "temperature": 0.2 } },
    "prompt": "...",
    "sources": [...],
    "profile_snapshot": {...},
    "recommendation_text": "...",
    "integrity_hash": "..."
  }
}
```

## Replacing Mock Services

### Retrieval Service
Edit `server/src/services/retrieval.ts` and replace `retrieveDocs()` with calls to:
- Searchable API
- Verisense document index
- Your own RAG system

Ensure returned docs include: `source_id`, `title`, `url`, `excerpt`, `score`.

### LLM Service
Edit `server/src/services/recommendationLLM.ts` and replace `generateLLMResponse()` with:
- Cerebras API calls
- OpenAI API calls
- Your preferred LLM provider

### Profile Service
The `verisenseClient.ts` already uses your existing `/api/verisense/profile/:id` endpoint. No changes needed unless you want to modify the fallback behavior.

## Verification

The integrity hash can be verified by:
1. Reading the recommendation JSON file
2. Removing the `integrity_hash` field
3. Computing `SHA256(JSON.stringify(rec))`
4. Comparing with the stored hash

This ensures the recommendation hasn't been tampered with.

## Index File

The `logs/recommendations/index.json` file maintains a list of the last 200 recommendations for quick lookup:
- `id` - Recommendation ID
- `user_id` - User ID
- `query` - Original query
- `created_at` - ISO timestamp
- `path` - Relative path to full evidence file

## Demo Mode

The system works in demo mode without external API keys:
- Profile fetching falls back to mock data if Verisense is unavailable
- Retrieval uses mock documents
- LLM uses mock responses (or existing LLMService if OpenAI key is configured)
